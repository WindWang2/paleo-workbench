Paleo Workbench — Architecture Review

Deepening opportunities for testability, locality, and AI-navigability

2026-07-23

Executive Summary

Following recent developments across Seismic Time Profile Acceleration, 3D Geological Modeling, and Multi-Well Correlation, the core domain logic has grown significantly. We identified 3 key areas where shallow helper classes and manual PySide6 UI state orchestration create friction. Deepening these modules will concentrate complexity behind clean domain seams.

#1

Unified Stratigraphic Correlation Engine

Strong

Involved Files

  • • paleo_workbench/viz/well_section_datum.py
  • • paleo_workbench/viz/formation_top_correlator.py
  • • paleo_workbench/viz/dtw_log_matcher.py

Problem

Multi-well stratigraphic correlation currently relies on 3 separate thin helper classes. Callers must manually orchestrate datum shift transformations, DTW curve normalization, index transfers, and polygon quad calculations across separate calls.

Solution

Unify DTW matching, datum flattening, and inter-well polygon quad calculation into a deep StratigraphicCorrelationEngine module behind a simple correlate_section(wells, mode, target_horizon) interface.

Benefits (Locality & Leverage)

Concentrates depth coordinate math, DTW alignment, and polygon quad generation into a single deep module. Tests can verify multi-well correlation logic through a headless domain interface without UI setup.

#2

Geological 3D Scene Management Engine

Worth exploring

Involved Files

  • • paleo_workbench/ui/pages/geological_modeling_3d_page.py
  • • paleo_workbench/viz/geomodel/engine.py
  • • paleo_workbench/viz/geomodel/well_seismic.py

Problem

GeologicalModeling3DPage directly manages pyqtgraph.opengl GLGraphicsItem instances in raw python lists and dict maps (active_items, mesh_items_map, _well_curve_items), entangling UI host code with OpenGL item lifecycle management.

Solution

Encapsulate OpenGL items, volume clipping, camera positioning, and tree visibility synchronization behind a deep Geological3DSceneEngine adapter.

Benefits (Locality & Leverage)

Maximizes UI locality by removing raw OpenGL item manipulation from PySide6 page handlers. Enables headless testing of 3D scene node creation and visibility trees.

#3

Paleo Map Topology & Repair Kernel

Speculative

Involved Files

  • • paleo_workbench/ui/pages/map_edit_topology.py
  • • paleo_workbench/ui/pages/map_edit_scene.py
  • • paleo_workbench/ui/pages/map_edit_commands.py

Problem

2D map editing snapping, node alignment, topology validation, and draft undo/redo commands are split across 5 separate modules, requiring message chains between scene items and topology panels.

Solution

Consolidate shared-node topology validation, vertex snapping, and self-intersection repair into a unified PaleoMapTopologyEngine.

Benefits (Locality & Leverage)

Eliminates shotgun surgery during map editing feature additions and centralizes topology repair algorithms into a pure, testable domain kernel.

Top Recommendation: Candidate #1

We recommend starting with Candidate #1 (Unified Stratigraphic Correlation Engine). Following the recent implementation of WellSectionDatum, FormationTopCorrelator, and DTWLogMatcher, consolidating them into a deep StratigraphicCorrelationEngine will immediately simplify StratigraphyCorrelationPage and provide high leverage for future multi-well features.
