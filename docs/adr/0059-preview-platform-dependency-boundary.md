# 预览的平台依赖边界：视频靠系统编解码器，.doc 明确不支持

数据管理资产预览增强（视频播放、Office/PDF 复制）中，视频支持注册 `mp4/mov/webm/mkv/avi` 容器并交给 Qt Multimedia 播放，但**不捆绑任何解码器**：能否解码取决于运行平台的系统编解码器（Linux gstreamer / Windows Media Foundation），缺失时降级为明确诊断消息（文件路径可复制），而非静默失败。旧版二进制 `.doc` **明确不支持**，给出"请另存为 .docx"的诊断；`.docx` 通过引入纯 Python 依赖 `python-docx` 解析为纯文本预览。

原因：捆绑解码器（或解析 OLE 复合文档）的体积、许可与维护成本与"初步预览"的收益严重不成比例；不声明边界的话，缺解码器的机器上视频"打不开"会被当成 bug 反复排查，`.doc` 也会被反复提议支持。注册常见容器成本近零，能不能播交给平台。
