# feat(mapping_kernel): bounded ring clip and closure/orientation repair without shapely

## 用户流程（本切片验收）

用户在域环（clip_ring）内裁剪等值线/相带多边形、或保存自交/未闭合的相带面时，
Python 产品经 `geometry_operations.clip_polygon_to_ring` / `clip_polyline_to_ring`
与 `topology.repair_invalid_geometry` 处理几何。本 PR 把其中**不依赖 shapely 的
子集**移植进 Qt-free/GEOS-free 的 `libs/mapping_kernel`（ring_ops），使 C++ 侧
在同一类输入上与 Python 结果一致：

- `repair_invalid_geometry` 的闭环 dict 段（逐字移植，含 `<3 坐标环` 的恒等回退）
  与 valid 路径的 signed-area 定向（外环 CCW / 洞 CW）；
- **有界自交拆分**：单一 proper crossing 的 bowtie → 两瓣 MultiPolygon（与
  shapely 2.1.2 `make_valid` 的输出实证吻合，含非整交点案例）；
- `clip_polygon_to_ring` / `clip_polyline_to_ring` 的有界子集：简单非退化输入上的
  边界弧拆分 + even-odd 侧分类 + 度 2 节点缝合 overlay（含洞、MultiPolygon、
  多件结果、空结果 None）。

越界输入（自交环、顶点触边、共线重叠、洞越界、退化零面积环等）一律返回
`unsupported` + 结构化原因——绝不静默给出错误几何；这些 shapely-only 案例在
测试中**显式 skip 并打印原因**。

## Oracle（真实 Python 冻结）

`tools/oracle/generate_ring_ops_fixtures.py` import **真实产品码**
（`repair_invalid_geometry` / `clip_polygon_to_ring` / `clip_polyline_to_ring`，
shapely 2.1.2，无 monkeypatch——对比 M6 第三片把 repair 冻结成 identity 的
限制，本切片正是补上这一缺口）。**51 个案例 = 35 portable（C++ 必须对账）+ 16 shapely_optional（C++ 显式 skip 记录）**，分类按输入形态（自交计数/触边/
共线检出）判定，从不参考 C++ 输出。比较用规范化坐标集合（环旋转归一 +
|面积|最大者为外环 + 外环 CCW/洞 CW + 片段方向归一），坐标容差 1e-9。

## 边界与诚实声明

- `unsupported` 分支是 C++ 契约（英文 reason 供测试/日志断言）；Python 侧的
  异常文案在 fixture 中存档（`python_error` 字段），不做跨语言字符串互译。
- GEOS 输出的环起点/片段顺序是实现细节，非用户契约——比较采用集合语义
  （与 `test_geotopo_parity` 的面积多重集先例一致）。
- 三轮审核（正确性+完整性自审、对抗性 spec 审核、Karpathy 质量审核）记录在
  `docs/development/cpp-conversion-swarm-20/ledgers/04-*` 与 `.goal-loop-ledger.md`。
