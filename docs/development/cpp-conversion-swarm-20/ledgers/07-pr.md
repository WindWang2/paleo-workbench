# feat(workflow_engine): in-memory DAG engine with interpolate_factor node and failure short-circuit

## 用户流程（本切片验收）

一个两节点 spec（**extract → idw**）在 C++ 引擎里跑完：`map.extract_factors` 节点
包装 `pwb::mapping::extract_factors`，`map.interpolate_idw` 节点包装
`pwb::mapping::interpolate_factor`（CRS 经 `$ref` 从 extract 输出链式流入，同
Python 的 dataset.crs 语义），产出 **typed FactorGrid**（`std::any` 载荷 + Json
投影）；**失败节点阻止下游**——extract 产出 0 点时 interpolate 抛 Python validate
同款消息，该节点 FAILED、下游 SKIPPED、run FAILED；取消（op 内检查点 / 节点边界 /
预取消三窗口）→ run CANCELLED 且已完成节点诚实保留 SUCCEEDED。

- 内存引擎：拓扑序（Kahn、spec 序 tie-break）、失败短路（`_skip_dependents`
  不动点）、协作取消（`CancelToken`）、每个节点的 stdout 级日志（可注入 sink）。
- 节点体 = 显式函数注册表（无静态自注册）：`test.noop` + 两个 mapping_kernel 包装。
- 最小 JSON spec（node_id/op/params/depends_on + `$ref[key]` 绑定）；06
  （libs/workflow_spec）落地后的合流点在 `07-decisions.md` D2 声明。
- 明确不做（decisions D1-D4）：SQLite/JSON store、resume/rerun、缓存身份、重试、
  条件、并行驱动、TaskScheduler 桥。`libs/workflow` task_runtime 对外契约未动。

- **11 组校验问题列表**（真实 `validate_workflow_spec` 输出逐字对账）
- **2 条运行期绑定错误消息**（真实 `resolve_value`/`BindingError`）

C++ 测试 `workflow_engine.run`：14 组场景（2 链 + 线性序 + 菱形 + 冻结消息失败链 +
op 失败扇出 + op 内取消 + 预取消 + 校验消息 + 绑定失败 + from_json 往返 + 空
outputs ref + 整包 ref + 直接 op 调用解析面）。
