# feat(mapping_kernel): representative facies and point-to-surface descriptors on existing class grid

CONV-10（cpp-conversion swarm #10）。移植 `paleo_workbench/mapping/well_prediction_surface.py`
的**纯数据部分**到 `libs/mapping_kernel`，栅格一律复用已冻结的
`nearest_neighbor_class_grid`（零改动），多边形核复用 `classify_grid` / `polygonize_class` /
`shoelace_area` / `round_to` / `crs_is_geographic`（全部零改动）。

## 用户流程（本切片验收面）

一组井区间记录（result_summary.predicted_regions / spatial.intervals）→
`representative_facies` 选出代表相（累计厚度优先、再比平均概率、层位子串过滤）→
`nearest_neighbor_class_grid` 生成分类栅格 → `point_features` / 点到面多边形
GeoJSON 描述符，与 Python 逐案例一致。UI/Qgs 接线与井注册表胶水（`well_xy`、
`_wells_for_task`、`well_facies_points` 编排）按主计划分层留在 Python 侧。

## 与 Python 的声明偏离（详见 10-decisions.md）

- shapely `repair_invalid_geometry`（= identity）与多边形级 `clip_polygon_to_ring`
  不复制——沿 polygonization 切片先例；格级 inclusive 裁剪由
  `nearest_neighbor_class_grid` 承担（class_grid_oracle 已冻结 clip_square）。
- 真值非 dict 的 `properties` 按丢弃处理（Python dict() 强转/抛错，病态 JSON 域外）。
- Unicode 十进制数字位（`float("１２３")`) 不复刻（有界实现，name_search 先例）。

## oracle 案例数

51（generator 输出行：25 representative + 6 task-region + 3 spatial-point +
3 point-feature + 6 extent + 8 surface）。
