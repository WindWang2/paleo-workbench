# feat(well_science): well curve operation kernels ported with oracle

CONV-11（cpp-conversion-swarm-20 任务 11）：把 `paleo_workbench/workflow/`
中测井曲线解释的**无 UI 数值/规则核**忠实移植到 Qt-free 的 `libs/well_science`，
全部冻结在真实 Python oracle 上。

## 用户流程验收（本切片）

对一条 LAS 风格深度-曲线数组做本模块公开运算，C++ 与 Python 数值一致：

- 平滑/滤波：`moving_average`（numpy 'same' 偏移逐位复刻）、`median_filter_curve`
  （scipy reflect=对称镜像边界逐位复刻）
- 归一化/裁剪：`normalize_curve`（zscore/minmax + 退化语义）、`clip_outliers`
  （numpy percentile linear 含 t≥0.5 lerp 分支；NaN 边界传播）
- 单位换算：`normalize_unit_name` / `conversion_factor` / `convert_values`
  （显式白名单 + 逐字冻结的拒绝文案）
- 重采样：`resample_axis`（尾部不足一步丢弃；下降轴/坏 step 拒绝）
- 插值：`interp_nan_aware`（显示桥接语义，已废弃但被 UI 消费）与
  `interp_gap_preserving`（V6 §4 科学语义：内部空洞绝不桥接）
- 诊断：`missing_interval_report`（含 NaN 端点时 order-dependent 的 largest_gap）
- 派生曲线：`evaluate_curve_expression`（受限文法递归下降解析器，复刻 Python
  visitor 的比较折叠顺序与 NumPy 元素级语义，绝不 eval）
- 深度单位门：`classify_depth_unit` / `require_depth_unit` / `depth_unit_of` /
  `UnknownDepthUnitError`（V6 P0-3：unknown 永不猜测为米）
- Null 政策：`NullPolicy` / `null_policy_from_declared`（declared/inferred/
  derived_injected/none 四态；np.isclose rtol=0 atol=1e-6 匹配）
- curve_interpretation 纯核：`depth_shift`（ft 轴先换算米位移）、`despike`
  （MAD 尺度 + 1% ptp 下限）、`baseline_shift`、`CURVE_OPERATIONS`/
  `OPERATION_SCOPE` 元数据表

不移植（findings 分类）：`apply_curve_operation`/`_ensure_writable_well_header`
（catalog+lasio 工程对象）、well_qc 行规则（井表流，公式归属 geo-viz-engine 契约）、
viz 三文件的工程对象（native_backend 已有 C++ 双路径；layout 归 M8 viz 切片）。

## Oracle

`tools/oracle/generate_curve_ops_fixtures.py` 用真实生产模块（numpy 2.5.3 /
scipy 1.18.1 venv）冻结 **291 案例** → `libs/well_science/well_science_tests/
fixtures/curve_ops_oracle.json`，覆盖每个公开函数与每个失败分支（含逐字错误
文案；生成器保证所有期望值来自 live 模块，`allow_nan=False` 拒绝裸 NaN 字面量）。
另有 7 条 audit-regression 直接断言钉住 numpy 内部 TypeError 类分支的 C++ 契约。

## 审核

三轮（账本 11-15 行）：① 对抗性正确性/完整性（subagent，3×P1 + 9×P2，全修：
median_filter 反射公式、moving_average 非有限 0 贡献、clip NaN 传播、clip 2 参
TypeError 语义、关键字检查先于求值、py_repr 对齐 str(float)、长度失配防护、
depth_unit_of 文档语义修正）；② 完整性复核（每符号每失败分支有冻结案例）；
③ Karpathy 代码质量（P1=fixture 手写期望值违反 oracle 纪律 → 改由 live 属性
冻结；P2×3 全修）。全部发现与修复记录在
`docs/development/cpp-conversion-swarm-20/ledgers/11-decisions.md`（D1-D19）
与 `.goal-loop-ledger.md`。

## 边界

- 根 CMake 只追加 `BEGIN CONV-11 … END CONV-11`（option `PWB_BUILD_CONV_11`）。
- 不动 mapping_kernel 已绿核；不依赖线上 CI；不开 GitHub workflow。
- 已知边界（decisions D19）：`!r` 转义只支持简单 token；hex/underscore 字面量
  C++ 拒绝（Python ast 接受，两侧均安全）；numpy 内部 TypeError 文案不冻结。
