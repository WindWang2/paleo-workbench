# 15 — Catalog GC / payload dedup / entity 分页（M4 余项，conv-15）

分支 `feat/cpp-conv-15-catalog-gc`（BASE = origin/main `35987e13`）。

## 用户流程验收

**写入重复 payload 的两个版本，GC/dedup 后存储占用与 Python 规则一致；entity 列表分页稳定。**

- C++ `place_managed_file`：第二次写入相同内容（同尺寸 + 调用方 digest + 内容重证明）
  时零拷贝采纳共享只读 blob —— 版本 path 指向 `blobs/<d[:2]>/<d>`，物理上只有一份
  payload（oracle 场景 `dedup_flow`/`place_rules` 冻结了 Python 侧同流的全部产物）。
- GC/dedup 后的存储账目与 Python 逐字节一致：`blob_metrics`（blobs_on_disk /
  bytes_on_disk / referenced_digests / unreferenced_blobs / bytes_deduped）、
  `plan_blob_gc`、`sweep_unreferenced_blobs` 的删除集合全部对账冻结值。
- entity 列表分页：`search_assets_page` / `count_assets` 在真实 catalog.sqlite 文档上
  对 34 条冻结查询（排序白名单全序、keyset 游标、offset 分页、text/tag/stage/type/
  trash 过滤、NULLs-first、limit/offset 钳制、20 键行形状）逐行逐字段对账 Python。

## 方法（与已落地 mapping_kernel 一致）

纯算法核 + 冻结 Python oracle + C++ 对账。oracle 生成器
`tools/oracle/generate_catalog_gc_fixtures.py` 用**真实 Python 服务**
（`DataCatalogService` + `catalog.gc` + `catalog.dedup` + 分页 API）构建 4 个场景
工程树（含 catalog.sqlite/payload/孤儿/租行），全部期望值来自真实模块输出，零手写；
C++ 测试 `data.catalog_gc` 拷贝同树、经 `CatalogRepository` 读同一 store 复放对账。
