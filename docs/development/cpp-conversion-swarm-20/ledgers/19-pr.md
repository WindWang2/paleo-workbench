# CONV-19 — 资源扫描/井顶/井位 XML 纯解析核(feat/cpp-conv-19-ingest-parsers)

## 用户流程(本切片验收)

给定仓库内真实/测试 XML 或井顶文本,C++ 解析出的点/曲线头与 Python 一致:

- **井顶文本**(`parse_well_tops`):SMI WellTops .dat → 分层点(容忍 CRLF/注释/垃圾行),真实 fixture `tests/fixtures/realdata/DC.dat` 对账通过。
- **井位 XML**(`extract_well_locations_xml`):通用/SpreadsheetML XML → 显式井坐标记录(井名 + X/Y,CRS 静默 4326 收敛语义保留),坏 XML 走用户面 warning。
- **测井 XML 识别**(`is_well_log_xml`):WITSML/测井 SpreadsheetML 内容识别(文件名无关),喂给 `classify_import_path` 的 well_head/well_log 认领链。
- **预览**:registry.build_preview 全路由端口——文本/CSV/TSV/DAT(SMI 表头剥离)/Markdown/JSON/BOM;SpreadsheetML 有界表格(边界截断保留部分行);WITSML/表格 XML 曲线头;zip/pptx(缩略图+幻灯片数)/dfb(同名兄弟图/内嵌 PNG/JPEG 结构验证)预览;doc/geotiff/excel/las/docx/segyio 缺依赖回退按 D4/D8 冻结为 C++ 长期语义。
- **资源扫描识别**:`classify_path`(全部扩展名/CJK 关键词/路径段分流)+ `classify_import_path`(XML 内容探针)。
- **路径穿越拒绝**:`resolve_project_path`/`relativize_path`/`is_within_directory` + registry 资产路径解析(`../` 逃逸拒绝,与 Python `ProjectPathError` 同语义)。
- **PreviewSettings**:校验(density/theme/15 组整数界/bool 严格型)+ canonical fingerprint(SHA-256 前 16 hex,与 `json.dumps(ensure_ascii=True, sort_keys=True)` 逐字节对齐)。

## Oracle

- 生成器 `libs/ingest/oracle/generate_ingest_oracles.py`:**全部期望值来自真实 Python 实现的执行结果**(well_tops_parser / well_location_xml / well_log_xml / classifier / io_registry / preview_parsers.table_parsers·document_parsers·office_parsers / registry.build_preview / PreviewSettings / shlex / format_size;坏 ZIP 用 `zipfile`+`struct` 构造后仍由真实 Python 预览代码判定)。生成器内无任何手写期望字面量。
- geoviz 级联(PySide6)阻塞 registry/well_log_parsers 的常规 import;按 D2 以 sys.modules 站位父包后**按真实源码文件执行**——被测代码路径不经任何 stub。`joint_well_parsers` 因结果类型构造自 geoviz 无法诚实冻结,**不移植只读**(D3,findings §23)。
- 冻结案例:**249 案 / 314 次比较**(19 组:well_tops 13、well_location_xml 13、well_log_xml 9、classify_path 60、classify_import 6、project_paths 14、previews 40、spreadsheetml 12、xml_well_log 7、image_validators 7、office 19、registry 30、settings 15+、shlex 22、markdown_direct 8、format_size 9、常量表全量对账)。
