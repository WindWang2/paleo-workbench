# CONV-20 — mapping_kernel 的可选 pybind11 门面（`pwb_mapping_kernel`）

## 用户流程（本切片验收）

为已绿的 mapping_kernel C++ 核（`libs/mapping_kernel`，本分支 **零改动**，`git diff origin/main -- libs/mapping_kernel` 为空）提供可选 pybind11 模块 `pwb_mapping_kernel`：

- **编了扩展的环境**：`from paleo_workbench.mapping.geological_pipeline import HAS_CPP` 为 **True**；门面 `native_bind.py` 的 `interpolate_factor` / `extract_factors` / `nearest_neighbor_class_grid` 走 C++ 核，返回与纯 Python 相同的类型（`FactorGridResult` / `GeologicalFactorDataset` / 四元组）。现有 pytest 证明数值不降级。
- **未编扩展的环境**：HAS_CPP 为 **False**，同一套门面逐调用回退到生产纯 Python 实现；现有测试全绿、新测试整体 skip。产品管线模块（interpolator.py / pipeline.py / well_prediction_surface.py）**一行未改**——加速是显式 opt-in 的新门面，无任何默认行为变化。

Kriging 估计器诚实门控（D7/D19）：geoviz 引擎在场时普通 kriging 留在纯 Python（引擎 WLS 是不同估计器，C++ 核是 numpy-grid-OLS fallback 的移植）；geoviz 缺席或请求移动邻域时才走 C++。距离策略/注记一律以 Python `resolve_distance_policy`（pyproj 感知）为准。

## 构建（可选，默认 OFF）

```bash
cmake -S . -B build/conv-20 -G Ninja -DCMAKE_BUILD_TYPE=Release \
  -DPWB_BUILD_PLATFORM=OFF -DPWB_BUILD_DATA=ON -DPWB_BUILD_SCIENCE=OFF \
  -DPWB_BUILD_MAPPING_KERNEL=ON -DPWB_BUILD_CONV_20=ON -DBUILD_TESTING=ON
cmake --build build/conv-20 -j 2
ctest --test-dir build/conv-20            # 29/29
```

pybind11 v3.1.0 头（BSD-3）vendor 于 `libs/mapping_bind/_vendor/pybind11/`（构建机无 PyPI；仓内先例：sqlite amalgamation + nlohmann 单头）。
