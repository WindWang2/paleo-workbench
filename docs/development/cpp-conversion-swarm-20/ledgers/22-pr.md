# CONV-22 — geomodel 契约/写器核簇（domain / QC / exporters / advisor / lithology / 纯 builders）

## 用户流程（本切片验收）

M8 延续：conv-12 已移植 geomodel 几何核，本切片把 `paleo_workbench/viz/geomodel/` 剩余的**纯契约层**落入同一 `libs/geomodel`，Qt-free、运行时无 Python：

- **domain_contract**：`DomainObject` 全字段（well/horizon/fault/volume/tunnel/measure 六型合一）、`Provenance`、`meta()`/`from_meta()` 序列化往返、`object_from_spec`、`ModelAssembly`（object map + provenance index + `std::recursive_mutex` ≈ RLock + mutations/display）、`geometry_stats`、`_unique_slug`（Unicode `.lower()` 表 1460 条由生成器冻结进 `lower_map.inc`）、三个纯 builders（trajectory/simplified-vertical/fault-mesh，name 前缀的 DomainError 文案）。
- **qc_contract**：`QCIssue`/`QCReport` 四级严重度梯（BLOCKER/ERROR/WARN/INFO）、per-kind 检查（well stations 有限/MD 单调/零长段/稀疏/简化标识、fault/horizon/volume/tunnel/measure 各自检查）、`MIXED_UNITS` 空串语义、`NO_PROVENANCE`/`STALE_SOURCE`（Python list repr 引号格式）、`assert_exportable` 导出门（`QCBlockerError` 逐字 blockers 文案）；`except (IndexError, ValueError, TypeError)` 精确捕获集保留。
- **export_contract**：V2 写器 `export_volume_flac3d`/`export_volume_abaqus`/`export_mesh_obj`/`export_mesh_stl`/`export_mesh_vtp`（API 返回 `ExportWritten{file, sidecar_name, sidecar}` 不直接写盘）；read-back 校验器 `read_flac3d_grid`/`read_abaqus_inp`/`read_obj`/`read_stl`/`read_vtp`（复用 ingest `xml_scanner`，malformed XML 报 expat 风格 `line L, column C`）；`validate_export` 回读对账；structured-grid 生成（Python 节点/单元序一致，含零维）；legacy 合成 `export_to_flac3d`/`export_to_abaqus`。字节格式逐一对齐：OBJ `%.6f`+1-based faces、STL 80B 头+LE 三角数+float32、VTP `%.6f` 顶点/`format="ascii"`/`vtk-polydata-xml` sidecar、FLAC3D `G`/`Z B8`、Abaqus `*NODE`/`*ELEMENT, TYPE=C3D8`。
- **advisor_contract**：`check_boreholes`（井口/轨迹一致规则）+ `check_coplanar_faults`（法向夹角 + 平面距阈值，零法向 RuntimeWarning 路径按值保留）。
- **lithology**：GR/SONIC/DENSITY/AI 四表 + `sample_log_values`（层段/深度区间语义 + float32 赋值）。

排除（D14）：`scene_adapter.py`（Qt/GL 桥）、`analysis.py`/`demo.py`（geoviz 委托 + demo 采样）、已在 conv-12 的几何核、catalog/UI 接线。

## 构建（可选，默认 OFF）

```bash
cmake -S . -B build/conv-22 -G Ninja -DCMAKE_BUILD_TYPE=Release \
  -DPWB_BUILD_PLATFORM=OFF -DPWB_BUILD_CONV_22=ON -DBUILD_TESTING=ON
cmake --build build/conv-22 -j
ctest --test-dir build/conv-22 -R geomodel   # 2/2
```

`PWB_BUILD_CONV_22=ON` 隐含 CONV-12/19；`Pwb::Domain`/`Pwb::Ingest` 为合法前向引用（generate 期解析），PUBLIC 链接（契约头文件暴露 `pwb::domain::Json`）。

- **冻结 oracle**：`tools/oracle/generate_geomodel_contract_fixtures.py` 驱动**真实** Python 实现，冻结 **267 案例 / 1460 条 lower 映射**（`indent=1, ensure_ascii=False`）；`$FX` 占位；STL bytes 冻结为 `{"b64": ...}`；期望值无手写。重跑生成器逐字节一致（sha256 `5d9df6ed…` 不变）。


- 实现期修复的真实 parity 缺陷：`check_coplanar_faults` 的 `std::move(issues)` 在 `issues.empty()` 判定之前求值导致恒 PASS（移前算 status）；`object_from_spec` 原按 object_id 前缀分派校验，Python 实际按声明类——`kind=well` + `object_id="fault:x"` 须先抛 `'well:'` 前缀错（改声明式 check_prefix）；builders 签名改 ragged 行使 `(N,4)`/`(N,3)` DomainError 在核内抛出而非测试夹具越界崩溃。
