# CONV-26 PR — 数据/工作区/目录/项目生命周期闭环（C++ 无 Python runtime）

分支 `feat/cpp-data-workspace-catalog-closure`（BASE `origin/main@ff67dcf3`，main 未移动，无需 rebase）。

## 目标与用户流程

让 C++ 产品**不依赖 Python runtime** 即可管理项目数据主线。验收环（`data.lifecycle_e2e`
实测通过）：`C++ create project → 目录导入（计划+执行）→ run 注册+结果发布 →
workspace membership/pin → save → save-as（artifacts 迁移）→ reopen → SQL 分页 →
provenance/lineage → 一致性 audit + GC plan（零发现/零孤儿）`。

## Python 暂留及原因

- 全部 Python 数据链保留：oracle/fixture 生成器（`tools/oracle/generate_ingest_plan_
  fixtures.py` 驱动真实 Python）与兼容参考；旧 PySide6 产品的运行时。
- LAS/WITSML 井名 header 引擎（geoviz）：按 CONV-19 边界，C++ 走"引擎缺失回退"
  分支（D1）；真引擎接入前身份匹配限 medium/low 置信档。

## 本地测试结果

- data_suite 独立树 **27/27 ×2 绿**（21 基线回归 + paged_sql + ingest.parsers +
  ingest_plan(4) + lifecycle_ops(6) + lifecycle_e2e + metadata_scale）。
- oracle 确定性：生成器双跑 oracle.json sha256 相等；fixture 树零绝对路径（相对
  标记 `__PWB_INGEST_ROOT__`，任意 checkout 位置可回放）。

## oracle 案例数与覆盖面

- 分页：31 冻结查询（~279 断言，复用 CONV-15 paged_queries fixture）+ 双路径互证
  + keyset 深分页遍历等价。
- ingest：9 计划项场景（井×2、pre-seeded 重复、shapefile 族组、调查、tops/
  deviation 角色链、`._`/空文件/非 preferred 过滤）——纯计划逐字段、执行报告、
  SQL 分页、links/实体树、负载布局、幂等重跑全对账；另有取消/恢复行为用例。

## 资源控制方式

CMAKE_BUILD_PARALLEL_LEVEL=2、单 worktree 单重型构建、MemAvailable ≥ 8 GiB 准入、
12 万级 scale 测试为确定性 sanity（有界断言）非压测。
