# CONV-29 — Composer / Layout / Export C++ 化（PR 记录）

## Scope
把 CONV-02（02-decisions.md D-01）明确推迟的制图行为层清零：
`layout_export.build_layout_spec`、导出报告、QGIS layout 执行链、
screen/export parity、map-body/preview/validate 服务，以及 C++ UI 的
产品接线。数据核（libs/mapping_document）原样复用，未重写。

## Python surfaces replaced（处置见 29-findings.md）
* build_layout_spec / hybrid 分类 / 镜像门控 / 像素预算 / 报告 →
  `libs/layout_export`（Qt-free 行为核，oracle 冻结）。
* QGIS layout bridge 执行体 → 单一权威 `layout_spec_exec.cpp`
  （桥与 C++ 产品共用，D-02），桥行为零变化。
* map-body / preview / validate / parity 服务 → `libs/qgis`
  CompositionLayoutService（无 Python 主链）。
* composer renderer / export.py（SVG 兜底渲染器、Qt 页面导出）→
  **oracle-only / removal-candidate**（D-03 fail-closed 取代静默兜底）。

## Product wiring
“导出布局…”：A4 构图（标题/主图/图例/比例尺/指北针/图廓）由会话实时
状态（画布 extent/CRS、树序图层）组装 → validate（fail-closed 预检）→
parity（画布/导出差异）→ export（原生链）→ 状态栏报告（items/dimensions/
警告数/parity 摘要）。

## Known limitations
* C++ 链无 composer SVG 兜底（by design，D-03）：hybrid 构图导出返回
  ok=false + itemized 诊断，而非第二引擎页面。
* parity 为状态级（extent/CRS/图层序/可见性/grid/legend）；style 与标注
  渲染为 by-construction（共享 QgsProject 图层实例），报告中如实披露。
* 构图编辑器（registry/templates/components）仍属 Python UI 面，C++ 侧
  未建（接入时另行切片）；服务以 composition JSON 为边界。
