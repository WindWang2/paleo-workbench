# 09 — Data Manager UX

## 1. 视图模型

Data Manager（`ui/pages/data_page.py`）在既有"资产/表格视图"上新增
**实体视图**（默认），四层视图齐全：

```
WorkArea（工区根）
├─ 井（Wells）
│  └─ Well A
│     ├─ 井身/井位 well_head
│     ├─ 测井曲线 well_log（多成员，primary 加标）
│     ├─ 井斜 trajectory
│     ├─ 分层 tops
│     ├─ 时深 time_depth（active 标）
│     ├─ 中间产物（该井源下游的 INTERMEDIATE）
│     ├─ 预测/成果（DERIVED）
│     └─ 解释 interpretation
├─ 地震调查（Surveys）→ per-survey 角色
├─ 地质对象（Geological entities）
├─ 辅助数据（Auxiliary / unassigned assets 桶）
└─ 成果与导出（OUTPUT）
```

- 树数据源 = EntityViewService（lazy：根/井层从 project.wells 组装，
  展开井才拉 role slots；展开角色才拉版本列表）。
- 角色空槽显示"缺失"（如无 trajectory）—— 可作为数据完备性一目了然。
- 保留：资产表格视图（分页 SQL 模式不动）、版本视图、lineage 视图、
  回收站、tag 过滤。实体视图与表格视图可互切。

## 2. 交互要点

- 井节点右键：打开 WellDataView 面板（角色/版本/未提交编辑/过期成果）、
  批量导入到此井（ingest plan 预绑定实体）、重算过期成果（impact 列表 →
  recompute_plan 既有机制）。
- 版本节点右键：为什么存在（ExplainService 面板）、固定/取消固定、
  删除影响预览（delete_impact 对话框：下游清单 + 阻断项）、
  创建工作副本（edit session）。
- stale 徽标：井级聚合计数 + 展开明细（direct/transitive/pinned 区分）。
- 所有重查询走 revision 键控缓存（domain_signature + catalog_revision）。

## 3. GUI 线程纪律

- 树构建/展开：只允许点查/批量点查/分页查询；禁止 list_assets() 全量。
- 井索引（根层）O(W) 一次组装，井数上限 10k 量级可接受；超出走分页井列表
  （轻量身份查询）。
- Explain/Impact 面板：worker 线程计算，信号回传。

## 4. 与 #1269/#1277 的关系

实体树读取面不依赖 #1277 的 `list_asset_identities`（独立实现等价能力，
见 00-overlap-audit）。未分配资产桶的分页直接用既有 `search_assets_page`。
