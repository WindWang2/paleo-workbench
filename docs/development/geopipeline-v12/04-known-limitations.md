# V12-B 已知限制与后续工作

## 本轮明确未做（决策见 00-decisions.md）

1. **等值线未优化**（D1 选项 A）。`contouring.py` 的纯 Python 双层循环
   （`_marching_squares_pure_python`）保持原样：300² 全层 ~0.6s（本机）。
   等值线**三套实现**（geological_pipeline/contouring、vendored 引擎内嵌
   管线、geoviz 门面 extract_contour_lines）+ 两份 nice-levels 算法的统一
   是独立架构任务。黄金值基线 contour_smooth_100/200/300 已建立，下一轮
   直接可用。
2. **克里金邻域路径不使用 geoviz 引擎**（D3）：opt-in 邻域时变差函数是
   numpy grid-OLS 拟合（已用 degraded 标签披露），不是引擎的加权 WLS。
   geoviz 环境下同参数的邻域结果与无 geoviz 环境一致（同一路径），但与
   引擎全局拟合的变差函数参数可能不同。
3. **变差函数预处理仍是 O(N²)**：N=2000 时 ~0.35s（距离矩阵 + 网格搜索），
   与全局/邻域路径共用。N>5000 时它将成为主要成本与内存项（N² float64）。
   若未来需要，确定性对子采样（固定种子 + metadata 披露采样率）是候选方案
   ——本轮刻意不做（非瓶颈，且引入新的近似论证成本）。
4. **邻域 k 上限 256**：`_KRIGE_NEIGHBORHOOD_CAP`。请求更大 k（或仅设半径
   且样本密集）会被截断并披露（`neighborhood.capped`）。上限的选择是
   (k+1)² 逐目标系统的可解性/内存权衡，未经科学（变差函数基程）论证——
   需要大 k 的场景应显式评估。

## 环境相关限制

5. **本 Goal 验证环境无 geoviz 引擎**（geo-viz-engine 子模块未检出）：
   - 克里金默认路径 = 纯 numpy 回退；引擎路径（有 geoviz 时）只验证了
     "代码零改动 + 邻域分支在其之前" 的结构正确性，未在引擎环境下运行。
   - 四个敏感测试文件（interpolation_evaluation / v8 duplication CV parity /
     contour_draft / facies_legend）与 m6 对抗套件在本环境无法收集
     （需 geoviz_plots→matplotlib、OpenGL 等）；已用 stash 对照确认与
     本轮改动无关，且其克里金断言全部走引擎路径（本轮未触碰）。
   - m6 的两个多边形墙钟门禁（棋盘 50²<3s、噪声 100²<15s）以手工复现
     方式验证通过（0.358s / 0.443s）。
6. **黄金值克里金网格用 1e-5 容差而非字节闸门**：线程化 BLAS 的内核选择
   随进程历史在末位浮动（复现记录见 01）。跨 BLAS 实现/线程数重建基线时
   需重新校准该容差。
7. **跨机器的绝对墙钟不可比**：本机与侦察机差 2.4–9×（不同工作负载不同
   系数）。复杂度钉用墙钟**比**（机器无关常数）而非绝对值。

## 残余性能机会（下一轮候选）

8. **多边形化剩余 ~0.9s@150² 层路径**：分布在段追踪的 O(cells) Python
   循环（`pt_key` 8.5 万次）与逐几何 shapely repair。向量化段生成会改变
   环顶点顺序 → 破坏逐字节输出契约，需要先建立「规范化几何（排序后）」
   的对比层才能安全进行。
9. **克里金邻域路径的进一步常数压缩**：k=32 时 O(M·k²) 的距离/协方差装配
   占主导；按邻域签名分组（相同 kNN 集的目标共享 K 的 Cholesky）在规则
   样本/网格化场景可再省 2–5×，但随机散点下分组率不稳定，本轮不做。
10. **`_deduplicate_samples` 是 O(N) Python 循环**：N=2000 时 0.018s，非
    瓶颈；N>50k 时值得向量化。
