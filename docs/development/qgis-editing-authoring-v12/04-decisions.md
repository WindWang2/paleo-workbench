# 04 — 决策记录（Decisions）

格式：决策 / 理由 / 边界。影响"是否值得做"的争议项一律给出**推荐**，实施时按此执行。

---

**D1｜D-A 用"先取锚点"局部修复，不动函数签名。**
理由：崩溃根因是调用点的一次性求值顺序，不是接口设计问题；改签名（改为按 const 引用传 shared 再内部拷贝）会引入一次整表拷贝。局部修复已实测通过 M1/M2 全部用例。
边界：不把 `beginSharedDrag` 改成引用传参——它的移动语义是有意为之（拖动集合要转为成员）。

**D2｜画布当前层改为"幂等重推"，并新增桥查询 `current_layer_id()`。**
理由：`set_active_layer` 的"同值短路"是性能优化，但画布侧可能从未成功接收（D-B）；"id 未变即跳过"把一次**可能失败的**同步当成了成功。
边界：旧桥（无 `current_layer_id`）退化为"总是重推"（多一次 IPC，无关性能）；不引入新的状态副本，查询面只读。

**D3｜桥侧 `editLayerProvider` 增加"会话兜底"，但仅在唯一可编辑层时生效。**
理由：宿主链路再断一层也不会让编辑能力消失；与 `PwbIdentifyTool` 的去 `currentLayer` 依赖同构。
边界：多会话层时不自动选（避免"我明明点的是 A 却改了 B"）；兜底生效要写进手势 payload（可诊断）。

**D4｜数字化工具条全功能纳入，分两批实施。**
- 第一批（M5-A）：填充环、矩形/正多边形、圆弧（两点/半径）、删除环·删除部件·移动部件的画布拾取、捕捉几何到图层、修剪/延伸、偏移曲线、反转线方向、简化要素、平滑、分割部件。理由：全部是"几何算子 + 既有 digitizer/拾取框架"的复用，交互语义与 QGIS 一一对应，无新语义要发明。
- 第二批（M5-B）：旋转要素、缩放要素、剪切/复制/粘贴要素。理由：需要新的交互构件（变换手柄/剪贴板生命周期），且粘贴必须重新过角色门禁与字段映射（见 D5），风险与工作量显著高于第一批。
边界：**覆盖** `qgis-native-vector-authoring-v10/04-decisions.md` 的 D5（rotate/scale 与 copy/paste 曾判 DEFERRED）与本集用户要求"全部功能"——两项均在本集立项，只是排在最后一批。

**D5｜剪贴板粘贴必须重新过门禁与字段映射。**
理由：跨层粘贴的源层/目标层角色、字段 schema、CRS 都可能不同；绕过门禁会破坏 RAW 保护与地质不变量。
边界：同层粘贴走快速路径（仍过编辑会话写入门禁）。

**D6｜`topology` 工具条开关保留单一开关，但文案与提示同步说明双重语义。**
现状：该开关既下推 `QgsProject::topologicalEditing`（QGIS 语义：编辑期联动拓扑点），又作为保存期 Python 校验门的开关（`composite_editing.py:2420-2436`）——与 QGIS 语义不同。
决定：**不拆分**（拆分会改变既有保存语义，且用户已习惯），改为工具条 tooltip 与状态条 chip 写明"拓扑编辑（编辑期联动 + 保存期校验）"。
边界：若后续要拆，另开里程碑，本集只做文案与文档记录。

**D7｜标注序：回退栈统一为"帧末按图层序绘制"，并解析 `zIndex`；不追求 PAL 避让等价。**
理由：避让（obstacle/冲突求解）是 PAL 引擎能力，回退栈自研等价物收益低。
边界：`priority`/避让差异在标注对话框旁给出提示，并记入 07。

**D8｜删除 `_push_mirror_order` 旁路，栈序变更一律走组控制器 placement。**
理由：任何"第二条顺序通道"都会与树权威打架（D-C1 就是它少了反转）；V11 04-ordering 已确立单一来源原则。
边界：平铺模式仍需快速路径时，允许保留但**必须**与 `qgis_mirror.py:1124` 同式反转，且由 I-1 用例钉住。

**D9｜新增层落点改为"归属组内置顶"。**
理由：对齐 QGIS "new layer on top" 的用户预期；且与扁平模式（新层在领域列表尾 = 顶层）一致。
边界：既有断言 `tests/test_layer_tree_plan_v11.py:120-138`（`ids[-1] == "l_new"`）随语义更新；系统组内新增仍按模板带位（不置顶），避免破坏角色带序。

**D10｜回退面板语义对齐（行 0 = 顶层），本集不废弃。**
理由：废弃回退面板是独立工程（涉及无桥环境的全部 UX）；本集只需消除"两套面板方向相反"的认知陷阱。
边界：若后续决定废弃，迁移用例的工作在独立里程碑做。

**D11｜诊断脚手架收口为环境变量开关。**
理由：当前 TEMP-DIAG 每次 publish 写盘并 `canvas.grab()`（外加一次 JSON 树 dump），是性能与噪声隐患；现场调试仍需它。
决定：`PALEO_EDIT_DIAG=1` 开启，默认关闭；`snap_feedback` 由状态条消费（R7）。

**D12｜Windows 腿必须跑真桥编辑用例（CI 门）。**
理由：D-A 在 Linux 上根本不复现（求值顺序），全部既有验收记录都是 Linux 腿结论。不建立双平台门，同类缺陷必然重演。
边界：Windows 腿可只跑 `-m qgis` 子集 + 本集新增的编辑链路用例，不追求全量。

**D13｜拓扑相关"无 UI 面"能力统一在一个里程碑接线（M4）。**
对象：避免重叠、追踪、顶点档位、捕捉读数、`fault_cut`/`boundaryReshape`（geotopo 交互）。
理由：这些能力的 C++/服务层已完成，缺口只在表面与门禁；分散接线会重复三次同样的表面工作。
边界：`grid snapping` 保持 Python 专有（记录项，不下推），不接线。
