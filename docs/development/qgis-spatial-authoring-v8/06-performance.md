# 06 — Performance

机器：本机（Windows，i9/64GB）；PySide6 6.8.3 + 桥 0.4.0a0。
入口 `scripts/run_qgis_env.py`（静默机器——无并行编译时采集）。

## M6 增量发布无回归（既有门 + V8 复测）

tests/perf/test_mirror_publish_scale.py（slow 标记，fake 栈 = host 侧
payload 成本；预算为 V7 §9 既有验收线）：

| 场景 | n | 实测 ms | 预算 ms | 判定 |
|---|---|---|---|---|
| 全量首发（冷进程首例） | 50 | 103.2 | 60 | 冷启动 warmup（首个用例付模块装载）；同进程预热后 22.1ms ✅ |
| 全量首发 | 200 | 80.5 | 240 | ✅ |
| 全量首发 | 500 | 191.1 | 700 | ✅ |
| 全量首发 | 1000 | 477.7 | 1600 | ✅ |
| no-op 发布 | 50/200/500/1000 | 3.4 / 5.8 / 14.0 / 35.1 | 8/30/80/180 | ✅（1000 层 35ms，远低于预算） |

冷启动 50 层一例的 warmup 归因：同进程先跑 200 层再跑 50 层 =
22.1ms（预算内）；50 层只是参数化首例付一次装载成本。W1/W3 未触碰
mirror 发布路径代码（qgis_mirror/map_render_backend 零改动），无回归
来源。

## W1 typed 解析成本

手工按名构建（geometryFromGeoJson + setAttribute）与 OGR 解析同阶；
schema 化镜像层为 role 驱动（工作站用户层为主），全量首发预算上表已
覆盖。fields_json 解析失败（畸形 wire）按异常直抛，无静默重试。

## 结论

M6 验收线全部满足（no-op 不序列化完整 GeoJSON / 单要素走 delta / 预算
内）；真实 next hotspot 仍是冷进程首装的模块装载（非本 goal 面）。
