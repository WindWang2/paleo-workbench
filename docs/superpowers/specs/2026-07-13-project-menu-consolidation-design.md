# 工程操作并入菜单栏设计

## 目标

移除菜单栏下方独立的工程工具栏，避免工程操作按钮占用一整行垂直空间。保留全部现有项目生命周期能力，并将全局搜索保留在同一顶栏的右侧。

## 布局与交互

- `AppShell` 仅保留一行顶栏：左侧为“工程与文件、视图、工具、帮助”，右侧为全局搜索框。
- “工程与文件”由静态标签改为下拉菜单，依次提供：新建工程、打开工程、打开样例工程、保存工程、分隔线、工程属性。
- 菜单项通过 `MenuBar` 的五个语义信号触发；窗口继续连接既有 `_on_new_project`、`_on_open_project`、`_on_open_sample_project`、`_on_save_project` 与 `_on_properties` 处理器。
- 工程打开、新建、保存或加载样例后重建 `AppShell` 时，新的菜单栏必须重新连接，操作行为与迁移前一致。

## 组件边界

- `MenuBar`：负责菜单展示、搜索框和五个工程操作信号；不处理文件对话框或工程数据。
- `PaleoWorkbenchWindow`：保持项目生命周期、对话框和错误提示职责，仅将连接入口从工具栏改为菜单栏。
- `AppShell`：不再创建或布局 `HeaderToolbar`，从而彻底消除独立第二行。

## 兼容与清理

- 删除不再使用的 `HeaderToolbar` 实现和其公共导出。
- 相应测试迁移至 `MenuBar` 与项目生命周期测试；不保留已废弃工具栏的兼容壳。
- “视图、工具、帮助”保持现有展示范围，本次不新增其功能。

## 验证

- 顶栏布局中不再存在 `HeaderToolbar`，搜索框仍可见且位于菜单栏右侧。
- 五个“工程与文件”菜单操作各自发出正确信号。
- 新建或重建壳体后，菜单操作仍可到达窗口处理器。
- 现有新建、打开、样例工程、保存与属性展示的生命周期测试继续通过。
