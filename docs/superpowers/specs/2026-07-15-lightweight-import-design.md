# 轻量文件导入设计

**日期：** 2026-07-15  
**状态：** 已实施并验证

## 目标

让数据页的文件导入保持响应迅速：导入时只根据文件路径和后缀建立项目资源记录，不读取或解析文件内容。初始分类是项目数据的一部分，用户可在导入后继续调整。

本设计覆盖数据页的“导入文件”“导入文件夹”和拖放导入入口；不改变项目启动时的样例扫描或手动重扫行为。

## 非目标

- 不在导入时验证数据格式或提取数据内容。
- 不在导入时计算 SHA-256 或基于内容去重。
- 不改变现有的后缀及 `.dat` 目录提示所产生的初始分类规则。
- 不改变启动扫描与手动重扫的完整扫描路径。

## 方案选择

采用导入专用的轻量收集器。

- 仅跳过 SHA-256 的方案仍会使单文件导入遍历整个父目录，不能可靠消除目录很大时的卡顿。
- 先导入、后补做内容分析仍会消耗磁盘与 CPU，不符合导入阶段不分析内容的目标。
- 轻量收集器对单文件只处理被选中的路径；对文件夹递归枚举其中的文件。它只读取名称、后缀和文件系统元数据（当前为大小），不打开文件。

## 架构与数据流

1. 数据页保持现有后台 `QThread` 导入任务和完成后的单次 UI 刷新。
2. 三个导入入口改为调用轻量收集器：
   - 文件导入：逐个处理用户明确选择的文件，不扫描父目录中的其他文件。
   - 文件夹/拖放目录导入：递归枚举目录中的文件并逐个轻量处理。
3. 每个可访问文件使用现有分类器产生初始 `type`、`format` 和 `status`；保留其 `.dat` 路径规则。
4. 收集器构造 `ResourceItem`，仅含项目归档所需的路径、名称、初始分类、后缀、大小、外部路径标识及来源；`checksum` 为空，且不调用任何内容读取函数。
5. 导入服务仅使用规范化后的路径去重；同一内容但不同路径的文件允许并存。
6. 新增 `ResourceItem` 写入 `ProjectDocument.resources`，因此分类是持久化的项目内容。重新打开项目时直接使用已保存记录；用户后续调整分类会更新同一项目资源记录。

## 错误处理与兼容性

- 文件在枚举后消失、无法 `stat` 或无权限时，跳过该文件并添加警告，其他文件继续导入。
- 同一路径再次导入仍报告为按路径跳过。
- 轻量导入不会产生“按校验和跳过”的记录。
- 导入状态文案使用“归档文件”等不暗示内容解析的表述。
- 已有项目记录保持兼容；其中已有校验和可以继续保留，但不会在新导入中生成或参与去重。

## 验证

测试覆盖以下场景：

1. 导入不打开文件内容且不计算校验和。
2. 选取单个文件时，不枚举或导入同父目录的其他文件。
3. 导入文件夹时递归收集文件，并使用既有后缀/路径规则产生初始分类。
4. 新资源被加入并持久化为项目的 `resources` 内容，包含初始分类和大小。
5. 相同规范化路径仍会去重；相同内容、不同路径则可同时导入。
6. 启动扫描与手动重扫仍使用原完整扫描行为。
